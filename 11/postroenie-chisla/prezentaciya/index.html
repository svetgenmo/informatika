Задание 5:
алгоритм достраивает число

Алгоритм смотрит на запись числа N, выбирает одну из двух веток и достраивает запись. Получается R.
Решаем программой: разобрать правило, перевести его в цикл, забрать ответ.

Базовый уровень, один балл. Ответ — одно целое число.

как это устроено

Одно число, четыре действия

Правило (демоверсия 2027)

Строится двоичная запись N. Дальше:

  • а) если N чётное — слева и справа дописываются по две единицы;
  • б) если N нечётное — справа два нуля, слева единица.

Полученная запись — это R в двоичной системе.

Возьмём N = 13.

  1. 13 = 1101
  2. 13 нечётное — ветка б
  3. 1 + 1101 + 00 = 1110100
  4. 11101002 = 116

Ветку выбирает N, а не R: здесь N нечётное, а R = 116 чётное.

как читать условие

Признак и две ветки

В любом варианте условие устроено одинаково. Меняются три вещи — их и надо выписать первыми, ещё до кода.

Что меняетсяЧто бывает (по 13 разобранным вариантам)
система записидвоичная (9 задач), троичная (4)
признак ветвлениячётность самого N; чётность суммы цифр записи; делимость N на 3
что делает веткадописать цифры слева или справа; дописать цифру и заменить два левых разряда; дописать последние цифры самой записи; сосчитать число (остаток или сумму цифр), умножить, перевести и дописать

Первая проверка — пример из условия. Написали программу — прогоните её на числе, которое дано в примере. Сошлось — правило прочитано верно. Не сошлось — искать ошибку здесь, а не в ответе.

инструмент

Перевод в другую систему счисления

В двоичную — уже есть в Python

s = f'{n:b}'        # короткий способ
s = bin(n)[2:]      # bin даёт '0b1101',
                    # срез убирает приставку

Оба дают строку — это важно: дописывать цифры мы будем склейкой строк.

В троичную — пишем сами

def to3(n):
    s = ''
    while n > 0:
        s = str(n % 3) + s
        n = n // 3
    return s

Остаток от деления — очередная цифра, и приписывается она слева. Готовой функции для троичной записи нет, поэтому это подпрограмма: написали один раз — зовём сколько угодно.

Обратно — int(s, 2) и int(s, 3): строка и основание.

каркас

Правило превращается в цикл

for n in range(1, 1001):
    s = f'{n:b}'
    if n % 2 == 0:
        t = '11' + s + '11'
    else:
        t = '1' + s + '00'
    r = int(t, 2)
    #print(n, s, t, r)
  • признак — это if;
  • две ветки — if и else;
  • дописать — склейка строк;
  • перевести обратно — int(t, 2).

Дальше остаётся одна строка отбора — та, что зависит от вопроса. Каркас во всех задачах один и тот же.

А закомментированная строка #print(n, s, t, r) — не украшение. С неё начинается работа: следующий слайд.

проверка

Сначала убедиться, что алгоритм прочитан верно

Строка отбора пока не написана: сперва печатаем след цикла и сверяем с примером из условия.

for n in range(1, 101):   # пока немного

Сверяем с примером — и проверяем обе ветки. В условии дано: N = 13 даёт R = 116 — строка с 13 совпала. Но 13 нечётное, прошла только ветка б. Ветку а проверяем сами, на чётном числе из следа: 4 → 100 → обложить единицами → 1110011 = 115.

Не совпало

Столбцы показывают, на каком шаге разошлось: s — перевод, t — достройка, r — обратный перевод. Чужое число в t — перепутаны ветки или сторона приписывания; чужое в r — не то основание в int(t, 2).

Искать ошибку здесь, пока задача ещё не решается.

Почему range(1, 101)

На первом шаге нужен не ответ, а глазами читаемый след: сто строк видно, тысячу — уже нет, и пример из условия в ней не найти.

Пример из условия всегда маленький — сотни хватает.

Совпало — гасим печать и возвращаем большой диапазон, а дальше дописываем строку отбора:

for n in range(1, 1001):
    ...
    r = int(t, 2)
    #print(n, s, t, r)
    if r > 95 and (best == 0 or r < best):
        best = r

Не стирать, а закомментировать. Показался странным ответ — решётку снять, и след снова перед глазами. Набирать строку заново на экзамене некогда.

разбор

Демоверсия 2027: наименьшее R больше 95

def to2(n):
    return f'{n:b}'

best = 0
for n in range(1, 1001):
    s = to2(n)
    if n % 2 == 0:
        t = '11' + s + '11'
    else:
        t = '1' + s + '00'
    r = int(t, 2)
    #print(n, s, t, r)
    if r > 95 and (best == 0 or r < best):
        best = r
print(best)

Печатает 100.

best == 0 — «ещё ничего не нашли»: первое подходящее значение записываем без сравнения.

Почему не годится «взять первое подходящее»: R растёт не ровно. Соседние N уходят в разные ветки, и значения скачут — вот что считает цикл:

как ещё пишут

Отбор через max и min

Через «ещё ничего не нашли»

best = 0
    ...
    if r > 95 and (best == 0 or r < best):
        best = r
print(best)

Через min

m = 10 ** 9   # больше любого R
    ...
    if r > 95:
        m = min(m, r)
print(m)

Разница только в том, чем занять переменную до первого значения: для максимума хватает нуля, для минимума нужно заведомо большое число. Дальше max и min сами решают, менять ли её.

СпрашиваютВначалеВ цикле
наименьшее R больше Tm = 10 ** 9 if r > T: m = min(m, r)
наибольшее R не больше Tm = 0 if r <= T: m = max(m, r)
наименьшее N с R ≥ Tm = 10 ** 9 if r >= T: m = min(m, n)
наибольшее N с R ≤ Tm = 0 if r <= T: m = max(m, n)

Обе записи верны — пишите ту, которую держите в голове. Важно другое: в min и max кладётся r или n в зависимости от того, что спросили.

Шесть вопросов — и все шесть будут сегодня

Последняя строка подробно: «ближе всего»

Единственный вопрос, где в цикле держим две переменные: одна для сравнения, другая для ответа.

dist = 10 ** 9   # расстояние: пока
              # ничего не нашли
best = 0      # сам ответ
for n in range(1, 1001):
    ...
    r = int(t, 2)
    #print(n, s, t, r)
    d = abs(r - T)
    if d <= dist:
        dist = d
        best = n
print(best)

Правило демоверсии, порог T = 200:

  • abs — потому что «ближе» не значит «больше»: R годится с любой стороны от T, важна только разница;
  • сравниваем расстояния (dist), а запоминаем номер (best). Положить d в best — частая ошибка: напечатается расстояние, а не ответ;
  • знак <=, а не <: ближе четвёрки к 200 не подошёл никто, а таких n два. <= перезапишет ответ более поздним — останется 19, наибольшее, как и спросили. При < осталось бы 17.
ловушка 1

best = n или best = r?

Как теряют балл

Программа написана правильно, цикл верный — а сохраняется не то число, которое спросили.

Проверяющей машине всё равно, что решено верно: ответ не совпал.

Как не терять

Подчеркнуть в условии последнее предложение — там сказано, что указать.

Написав print(best), вернуться к подчёркнутому: спросили N — в best должно лежать n.

В практикуме, если перепутать, страница скажет прямо: «это R, а спрашивают N». На экзамене никто не скажет.

Где проходит граница

Четыре формулировки — четыре разных знака в условии отбора.

Эти слова — не украшение условия, а его часть. Переносите их в программу дословно, а не по памяти.

троичная запись

Задача целиком: троичная система

def to3(n):
    s = ''
    while n > 0:
        s = str(n % 3) + s
        n = n // 3
    return s

def ds(s):
    v = 0
    for c in s:
        v = v + int(c)
    return v
best = 0
for n in range(1, 1001):
    s = to3(n)
    if n % 3 == 0:
        t = s + s[-2:]
    else:
        t = s + to3(ds(s) * 2)
    r = int(t, 3)
    #print(n, s, t, r)
    if r > 520 and r % 2 == 1 \
       and (best == 0 or r < best):
        best = r
print(best)

Печатает 567.

Условие было такое: если N делится на 3 — дописать две последние цифры записи; иначе — сумму цифр, умноженную на 2 и переведённую в троичную. Найти наименьшее нечётное R больше 520. Обе подпрограммы позвались сами собой.

Сумму цифр можно и без цикла

ds = s.count('1') + s.count('2') * 2

В троичной записи цифр всего три: нули в сумму не идут, каждая единица даёт 1, каждая двойка — 2. Тогда подпрограмма ds не нужна вовсе.

А вот to3 так не свернуть: перевод в троичную систему — это цикл с остатками, готовой функции для него в Python нет. Потому она и подпрограмма.
