Разработка подпрограмм — практикум

10 класс, углублённый уровень. Занятие одиннадцатое — практическая работа. В прошлой паре функция в задаче была одна. Сегодня их в каждой задаче две: кирпич и функция, которая из него построена. Так и разрабатывают программы — сверху вниз, подзадача за подзадачей.

План на пару. Сначала тренажёр: шесть коротких задач о том, как функции зовут друг друга, — вызов внутри вызова, функция из функций, признак на кирпиче, печатающий кирпич, какая строка упадёт, поиск с ранним return. Потом четыре программы, в каждой две функции с оговорёнными именами. Проверяет их оболочка Проверка.bat из общей папки: она запускает программу на девяти наборах данных, а потом зовёт каждую твою функцию напрямую и смотрит, что та вернула. Интернет не нужен.

Часть 1. Тренажёр: как функции зовут друг друга

Шесть типов задач, по одной на каждый. Считать в уме или на бумаге: найди, какой вызов выполнится первым, подставь аргументы в параметры, а если функция внутри зовёт другую — досчитай сначала её. Ответ — всё напечатанное через пробел; True, False и None пиши так, как их печатает Python. Ошибся — ниже появится разбор рисунком: вызовы лесенкой, что каждый вернул, — и кнопка «Новые числа»: реши такую же ещё раз.

Часть 2. Как разрабатывать программу из функций

Сверху вниз: задача — подзадачи — кирпичи

Думаем в таком порядке, а в файле все def стоят выше основной программы. Каждая подзадача получает имя — и дальше о ней можно думать одним словом: «если палиндром, то…».

Договор функции

ФункцияПринимаетВозвращаетПример
rev(n)натуральное числочисло задом наперёд rev(120) → 21
is_pal(n)натуральное числоTrue или False is_pal(121) → True
days_in_month(m, y)месяц, потом годчисло дней days_in_month(2, 2024) → 29

Имя, что на входе, что на выходе — этого хватает, чтобы функцией пользоваться, не заглядывая внутрь. Порядок параметров — тоже часть договора: days_in_month(2024, 2) не упадёт, а тихо вернёт 31. Договор удобно записать первой строкой тела — строкой документации в тройных кавычках.

Кирпич проверяем отдельно

Две строки — и кирпичу можно доверять. Бери крайние числа: однозначное, с нулём на конце, самое большое. Проверил — убери эти print из файла. Оболочка делает то же самое: зовёт каждую функцию на своих крайних числах, и ошибка в кирпиче не спрячется за удачными данными программы.

Где стоит def

def calc только запоминает тело: имя twice внутри ищется, когда calc позвали. Порядок def между собой не важен — важно, чтобы все они были выше первого вызова.

Три ошибки разработки

  • Кирпич печатает вместо return. Наверх уходит None: half(x) + 1 — TypeError, а if is_leap(y): молча ложно.
  • Аргументы не в том порядке. Встают в параметры по порядку, а не по смыслу; число совпало — ошибки нет, есть неверный ответ.
  • «Не нашёл» внутри цикла. return -1 в else отвечает на первом же числе. «Нашёл» — return в цикле, «не нашёл» — после цикла.

Часть 3. Четыре программы

  • Сохраняй решения в свою папку под именами zadanie1.py … zadanie4.py. Заведи для этой пары новую папку — в прошлой были свои zadanie1.py.
  • Обе функции обязательны и с теми именами, что в задании. Оболочка вырезает из файла твои def и зовёт каждую напрямую на своих числах. Функции нет, она печатает вместо return или параметры стоят не в том порядке — задание не принято, даже если вывод программы верный.
  • Никаких приглашений в input(). Пиши input(), а не input("Введите число: ") — вывод читает машина.
  • Выводи ровно то, что просят: те же слова, тот же порядок строк.
  • Шапка (# Ввод:, # Вывод:, # Пример:) — по желанию. Если она есть, пример в ней оболочка проверит запуском.

Часть 4. Сдача

  1. Файлы zadanie1.py … zadanie4.py лежат в твоей папке, отладочные print из них убраны.
  2. В общей папке двойной щелчок по Проверка.bat.
  3. «Найти мои файлы» → «Проверить всё».
  4. Покажи учителю два экрана: тренажёр наверху этой страницы и итог оболочки.
Если вместо окна открылся текст программы — файл открылся в IDLE как код. Нажми F5, окно появится.

Оболочка показывает, на каких данных программа ошиблась и что должна была вывести, а если не так ведёт себя функция — какой вызов что вернул и что должен был. Исправляй и проверяй снова, попыток сколько угодно. Отметка: четыре задания — «5», три — «4», два — «3».

Подсказка: разработка подпрограмм

Сверху вниз

Задачу делим на подзадачи: основная программа пишется так, будто нужные функции уже есть, потом каждая функция — отдельно. Кирпич (rev, sumdiv, is_leap) — внизу, из него строится следующая (is_pal, is_abundant, days_in_month).

Договор

Имя, параметры по порядку, что возвращает. days_in_month(m, y) — сначала месяц, потом год: аргументы встают по порядку, а не по смыслу. Договор пишут строкой документации в тройных кавычках.

Кирпич проверяем отдельно

print(rev(7), rev(120)) на крайних числах — до того, как строить из него дальше. Проверил — убрал print.

Вызов внутри вызова

f(g(x)): сначала g, её результат — аргумент f. Функция из функций: вызовы изнутри тела досчитываются раньше, чем внешняя вернёт своё.

Порядок def

Имя внутри функции ищется в момент вызова: def между собой в любом порядке, но все выше первого вызова. Иначе NameError.

Три ошибки

Кирпич печатает вместо return — наверх уходит None. Аргументы не в том порядке — неверный ответ без ошибки. return «не нашёл» внутри цикла — ответ на первом же числе; его место после цикла.
