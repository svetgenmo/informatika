Инвариант цикла и документирование

Как написать цикл, чтобы он был верным,
и как записать, что он делает. 10 класс, углублённый уровень — занятие седьмое.

Два урока плана за одну пару: «Инвариант цикла» и «Документирование программ». Они про одно и то же: самая ценная строка документации цикла — та фраза, которая верна на каждом его витке.

Вспомним вклад из пары 4

total = 1000
year = 0
while total < 8000:
    total = total + total * 100 // 100
    year = year + 1
print(year, total)
проверка условияyeartotal
до цикла01000
после 1-го витка12000
после 2-го24000
на выходе38000

В каждой строке верно одно и то же: total — сумма на счёте через year лет. Переменные меняются, фраза — нет.

Инвариант — фраза, верная на каждом витке

Утверждение о переменных, которое верно перед каждой проверкой условия: до первого витка, после каждого и на выходе.

Не условие цикла

Условие на выходе становится ложным. Инвариант остаётся верным всегда.

Не «переменная, которая не меняется»

Меняется всё. Не меняется связь между переменными.

Выход + фраза = ответ. На выходе известно и то, и другое: total ≥ 8000 (условие ложно) и «total — сумма через year лет» (фраза верна). Значит, year — первый год, когда вклад дорос до цели.

Сумма цифр: фраза, которую видно в таблице

n = 5372
s = 0
while n > 0:
    s = s + n % 10
    n = n // 10
print(s)
nss + сумма цифр n
537200 + 17
53722 + 15
5399 + 8
51212 + 5
01717 + 0

Фраза: s + сумма цифр n = сумма цифр исходного числа. Проще: s — сумма уже оторванных цифр, n — то, что осталось.

На выходе n == 0 — подставляем в фразу: s + 0 = 17. Программа считает сумму цифр — это доказано, а не проверено на трёх примерах.

Строим цикл по фразе: три места

МестоВопрос к фразеСумма цифр
Началопри каких значениях фраза верна до первого витка? ничего не оторвано: s = 0
Шагкак сдвинуться к цели, чтобы фраза снова стала верной? оторвали n % 10 — прибавили к s
Выходкогда фраза превращается в ответ? n == 0 → while n > 0

Это и есть «составление цикла по заранее определённому инварианту» из плана: сначала фраза, потом код.

Степень двойки: фраза и граница

Наибольшая степень двойки, не больше N. Фраза: p = 2 ** k и p ≤ N.

k = 0
p = 1              # 2 ** 0 = 1 ≤ N
while p * 2 <= N:
    p = p * 2
    k = k + 1
print(k, p)

while p <= N

Лишний виток: на выходе p > N — фраза сломалась.

while p * 2 < N

Фраза цела, но на N = 16 выходим на 8: «не больше» — это <=.

Проверять фразу надо на границе: N = 1, N — точная степень двойки, N на единицу меньше степени.

Ловушка: накопитель стартует с чужого числа

Так — неверно

mn = 0
for i in range(K):
    x = int(input())
    if x < mn:
        mn = x

«mn — наименьшее из прочитанных» неверна уже до цикла. На 5, 8, 3 напечатает 0.

Так — верно

mn = int(input())
for i in range(K - 1):
    x = int(input())
    if x < mn:
        mn = x

Из одного прочитанного числа оно само и наименьшее — фраза верна с начала.

И номер первого наибольшего: строгое >. С >= равное число перезапишет номер.

НОД вычитанием: фраза, которой нет в коде

while a != b:
    if a > b:
        a = a - b
    else:
        b = b - a
print(a)
ab
1218
126
66

Фраза: НОД(a, b) не меняется. Общий делитель a и b делит и a − b — поэтому вычитание НОД не трогает.

Выход: a == b. А НОД двух равных чисел — само число. Из кода этого не видно; из фразы — сразу. Это задание 3 практикума.

Документирование: что писать в комментарии

Шум

i = i + 1   # увеличиваем i
# цикл
while n > 0:

Пересказ строки: читать надо, нового ноль.

Польза

# Инвариант: s — сумма
# уже оторванных цифр
while n > 0:

То, что верно, — и чего в строках не видно.

Комментарий, который врёт, хуже, чем никакого. В тренажёре есть такой тип: три комментария, один неправда.

Шапка программы — договор

# Ввод: натуральное число n
# Вывод: сумма цифр числа n
# Пример: 5372 -> 17
n = int(input())

Что дать, что получить и пример. Карточка задания в практикуме устроена ровно так же — это и есть документация.

Пример ценнее слов: его можно проверить запуском. Оболочка сегодня так и делает — берёт вход из примера, запускает программу, сверяет. Не сошлось — врёт либо программа, либо шапка.

Документация для людей и чужая документация

Как работаем

  1. Открываем практикум из общей папки — сначала тренажёр: шесть задач на чтение циклов, оценки за него нет.
  2. Пишем три программы в IDLE, сохраняем в свою папку как zadanie1.py, zadanie2.py, zadanie3.py.
  3. Запускаем Проверка.bat → «Найти мои файлы» → «Проверить всё».
  4. Показываем отметку с экрана.
В задании 3 обязательны строки # Ввод:, # Вывод:, # Пример: вход -> вывод и # Инвариант: ... перед циклом. Без них оболочка задание не примет, даже если программа считает верно.
