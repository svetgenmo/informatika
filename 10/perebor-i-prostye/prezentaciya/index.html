Перебор

Цикл по переменной, делители и простые числа.
10 класс, углублённый уровень — занятие шестое.

Три урока плана за одну пару: for по range мы уже писали, цифры числа доставали в прошлый раз. Новое сегодня одно, зато большое: перебор как метод решения — и задание 25 ЕГЭ как его экзаменационная форма.

range: три числа, а не одно

for i in range(5):           # 0 1 2 3 4
for i in range(2, 6):        # 2 3 4 5
for i in range(1, 10, 3):    # 1 4 7
for i in range(10, 0, -2):   # 10 8 6 4 2

Начало, конец, шаг. Без начала — с нуля. Без шага — по единице. Правая граница не входит никогда.

range(5, 1) — пусто: начало больше конца, а шаг вперёд. Идти вниз можно только отрицательным шагом.

Ловушка 1: до n или до n − 1?

Так — неверно

n = 6
for d in range(1, n):
    if n % d == 0:
        print(d)

Напечатает 1 2 3. Сама шестёрка потеряна.

Так — верно

n = 6
for d in range(1, n + 1):
    if n % d == 0:
        print(d)

Напечатает 1 2 3 6.

Самая частая правка сегодняшней темы — + 1 в range. И самая коварная: на 7 из 10 проверок разницы не видно.

for или while — одно и то же

for — шагов известно

for d in range(1, n + 1):
    if n % d == 0:
        print(d)

«Перебрать всё от 1 до n».

while — то же самое руками

d = 1
while d <= n:
    if n % d == 0:
        print(d)
    d = d + 1

Шаг делаем сами.

Любой цикл переписывается другим. Выбор — по удобству: известно число шагов — for; шаги считает задача («пока делится») — while.

Ловушка 2: что осталось в переменной

После while

i = 1
while i < 10:
    i = i + 1
print(i)      10

Первое неподошедшее значение.

После for

for i in range(1, 10):
    s = i
print(i)      9

Последнее пройденное.

for i in range(5):
    i = i * 10        # бесполезно: range выдаст своё
print(i)              40

Менять переменную внутри for нельзя — точнее, можно, но на следующем проходе range всё равно выдаст очередное. В while такая строка сдвинула бы шаги.

Половина ошибок — в старте накопителя: произведение с нуля даёт ноль, минимум с нуля даёт ноль. Старт — это «значение, когда ещё ничего не посмотрели».

Делители и простые

Перебор как метод.

Делители: перебрать всё от 1 до n

k = 0
for d in range(1, n + 1):
    if n % d == 0:
        k = k + 1
print(k)             # сколько делителей

Тот же цикл со s = s + d — сумма, с print(d) — список, с m = d — наибольший.

Делители ходят парами: 36 = 1 · 36 = 2 · 18 = 3 · 12 = 4 · 9 = 6 · 6. Один из пары не больше корня из n. Поэтому искать делитель достаточно, пока d · d ≤ n: для миллиона — тысяча проверок, не миллион.

У 36 пара 6 · 6 схлопнулась в один делитель — у точного квадрата делителей нечётное число: у 36 их девять, у 49 — три.

Простое число

Ровно два делителя: 1 и само число.

  • 1 — не простое: у неё один делитель.
  • 2 — простое, и единственное чётное.
prime = n > 1            # флаг ставится ОДИН раз, до цикла
d = 2
while d * d <= n:
    if n % d == 0:
        prime = False    # в цикле флаг только сбивают
    d = d + 1

Проверка по количеству делителей ещё честнее: посчитали — ровно два — простое. Тогда единица отпадает сама собой.

Ловушка 3: флаг, который сбрасывается

Так — неверно

for d in range(2, n):
    if n % d == 0:
        prime = False
    else:
        prime = True

Последний проход — d = n − 1, на него n не делится, и флаг снова True. Любое число «простое».

Так — верно

prime = True
for d in range(2, n):
    if n % d == 0:
        prime = False

Флаг ставят до цикла, в цикле только сбивают.

И даже правый вариант врёт на единице: range(2, 1) пуст, флаг никто не сбил — «простое». Единицу проверяют отдельно: prime = n > 1.

Разложение на множители

d = 2
while n > 1:
    if n % d == 0:        # делится — снять множитель
        print(d)
        n = n // d        # d НЕ двигаем: мог войти ещё раз
    else:
        d = d + 1
# n = 60:  60 --2--> 30 --2--> 15 --3--> 5 --5--> 1

Здесь шаг делает не счётчик, а само число — поэтому while. Составным d не окажется: все его простые множители уже сняты.

if вместо «пока делится»

Снимет двойку из 64 один раз и уйдёт дальше. Ровно эта ошибка ждёт вас во втором задании — оболочка подаст 64.

Задание 25 ЕГЭ: перебор с отбором

В демоварианте 2027: перебирать числа, большие заданного, в порядке возрастания и искать те, что являются произведением ровно двух простых множителей — с дополнительным условием на запись множителей. В ответ — первые пять найденных чисел и для каждого наименьший множитель.

Форма всегда одна: перебрать по порядку → проверить свойство → напечатать число и что-то рядом. Свойство почти всегда про делители.

for n in range(a, b + 1):        # внешний: отрезок
    k = 0
    for d in range(1, n + 1):    # внутренний: делители
        if n % d == 0:
            k = k + 1
    if k == 6:
        print(n)
На маленьких отрезках это делается в уме — так устроен шестой тип тренажёра. На экзаменационных — только программой: это третье задание сегодня.

Считать делители, не перебирая

Сколько делителейКакие числаПример
ровно 2простые2, 3, 5, 7, 11
ровно 3квадрат простого4, 9, 25, 49
ровно 4p · q или p³6, 10, 14, 15, 8, 27
нечётноеточные квадраты1, 4, 9, 16, 25

Это не для заучивания, а чтобы проверять себя: если программа нашла «число с тремя делителями» и оно не квадрат — программа врёт. На ЕГЭ такая проверка стоит дороже, чем ещё один запуск.

Для сильных: степень за считанные умножения

Сколько умножений нужно, чтобы посчитать x16? Пятнадцать подряд — или четыре, если возводить в квадрат: x² → x⁴ → x⁸ → x¹⁶.

r = 1
while n > 0:
    if n % 2 == 1:        # нечётная степень — снять одну x
        r = r * x
    x = x * x             # дальше работаем с квадратом
    n = n // 2

Тот же приём «пока n > 0: смотрим n % 2, режем n // 2», что и в разборе числа на цифры, только цифры двоичные. В сегодняшний практикум это не входит — оставляем тем, кто закончит раньше.

В каждом задании спрятана ловушка темы, и оболочка подаст именно те данные, на которых она вылезает: единицу, 64 и 194, отрезок, оба конца которого подходят, и отрезок, где не подходит ничего.

Как работаем

  1. Открываем практикум из общей папки — сначала тренажёр: двенадцать задач на чтение кода, оценки за него нет.
  2. Пишем три программы в IDLE, сохраняем в свою папку как zadanie1.py, zadanie2.py, zadanie3.py.
  3. Запускаем Проверка.bat → «Найти мои файлы» → «Проверить всё».
  4. Показываем отметку с экрана.
Приглашений в input() быть не должно: input(), а не input("Введите число: "). Вывод читает машина. Списков не нужно: числа копятся в строке, как траектория в прошлый раз.

Отметка: три задания — «5», два — «4», одно — «3». Попыток сколько угодно, оболочка каждый раз показывает, на каких данных программа ошиблась.
